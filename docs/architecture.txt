================================================================================
                    DETAILED BREAKDOWN BY ARCHITECTURAL TIER
================================================================================

1. INGRESS & ROUTING TIER:
   - Zero-Friction DNS: Uses public wildcard DNS (*.127.0.0.1.nip.io) resolving to 127.0.0.1.
     Eliminates any manual modification of /etc/hosts or Windows system files.
   - NGINX Ingress Controller: Exposes port 80 and terminates HTTP traffic, routing by Host header.

2. UNIFIED GATEWAY TIER (Control Plane):
   - Single Endpoint: Aggregates dozens of fragmented tools behind http://dashboard.127.0.0.1.nip.io/mcp.
   - Collision-Proof Namespacing: Automatically prefixes tools with upstream slugs (woo__, tasks__, utilities__).
   - Fine-Grained RBAC: Mutating actions (create_product, create_task) require the "admin" role.
     Members (like Alice) receive HTTP 403 Forbidden on write attempts while retaining read access.
   - Fault Tolerance: Individual upstreams can be disabled or crash without affecting other servers.
   - Immutable Audit Trail: Every invocation, whether allowed or blocked, is logged with caller identity,
     latency (ms), upstream server, and full JSON payload.

3. UPSTREAM MICROSERVICES TIER:
   - Independent Pods: Upstreams run as isolated containers inside Kubernetes.
   - Protocol: Standardized on Streamable HTTP MCP (2024-11-05 spec).
   - Zero Coupling: Upstreams never communicate directly with each other; all coordination flows through Gateway.

4. STOREFRONT & PERSISTENCE TIER:
   - High Availability: MariaDB runs as a Kubernetes StatefulSet with dedicated PVC storage.
   - Real Commercial Catalog: Pre-seeded with 8 active products featuring studio photography and responsive srcsets.
   - Multi-Tenant Support: Dynamically provisions secondary stores (store2) with isolated namespaces.
